# MoKnight — Video Editing & Motion Graphics Portfolio

مشروع Next.js + Supabase حقيقي (قاعدة بيانات، مصادقة، تخزين ملفات) لمعرض أعمال مونتاج وموشن جرافيك، مع لوحة تحكم للمالك.

## 1. المتطلبات

- حساب مجاني على [Supabase](https://supabase.com)
- حساب مجاني على [Vercel](https://vercel.com) للنشر (أو أي مضيف يدعم Next.js)
- Node.js 18+ إذا أردت التشغيل محليًا

## 2. إعداد Supabase

1. أنشئ مشروعًا جديدًا في Supabase.
2. **قبل التنفيذ:** افتح `supabase/schema.sql` وعدّل السطر اللي فيه `'you@example.com'` (تحت تعليق 🔴 REQUIRED) ليطابق بالظبط الإيميل اللي هتحطه في `OWNER_EMAIL`. هذا هو الإيميل الوحيد اللي هيكون له صلاحية كتابة على قاعدة البيانات — الفحص ده بيحصل جوه قاعدة البيانات نفسها (RLS) مش بس في كود التطبيق، فحتى لو حد عمل حساب جديد عن طريق الخطأ، مش هيقدر يلمس أي بيانات.
3. اذهب إلى **SQL Editor** والصق محتوى الملف `supabase/schema.sql` ثم نفّذه. هذا ينشئ الجداول، الصلاحيات (RLS)، وحاويات التخزين (videos, thumbnails).
3. **مهم جدًا (الأمان):** اذهب إلى **Authentication → Providers** وأوقف "Allow new users to sign up" (تعطيل التسجيل العام). ثم اذهب إلى **Authentication → Users** وأنشئ يدويًا مستخدمًا واحدًا فقط ببريدك الإلكتروني وكلمة مرور قوية — هذا هو حساب المالك الوحيد.
4. من **Settings → API** انسخ `Project URL` و `anon public key`.

## 3. متغيرات البيئة

انسخ `.env.example` إلى `.env.local` واملأ القيم:

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
OWNER_EMAIL=your-email@example.com   # يجب أن يطابق بريد الحساب الذي أنشأته في الخطوة السابقة
```

## 4. التشغيل محليًا

```bash
npm install
npm run dev
```

افتح `http://localhost:3000` للموقع العام، و `http://localhost:3000/login` لدخول المالك.

## 5. النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. من Vercel: New Project → اختر المستودع → أضف نفس متغيرات البيئة الثلاثة → Deploy.

## ما الذي يغطيه هذا المشروع فعليًا

- مصادقة حقيقية عبر Supabase Auth، مقيّدة ببريد إلكتروني واحد فقط (`OWNER_EMAIL`) عبر `middleware.ts` وتحقق مطابق في كل Server Action.
- حماية خادمية حقيقية: كل عمليات الإضافة/الحذف/النشر تمر عبر Server Actions تتحقق من الجلسة، وليس أزرارًا مخفية في الواجهة فقط.
- قاعدة بيانات Postgres حقيقية عبر Supabase، مع Row Level Security بحيث الزوار (anon) لا يمكنهم القراءة إلا للمشاريع المنشورة وغير المخفية، ولا يمكنهم الكتابة إطلاقًا.
- تخزين ملفات حقيقي (Supabase Storage) للفيديوهات والصور المصغرة.
- نظام مسودة/نشر لإعدادات الموقع (`site_settings.draft` و `published`) مع زر استعادة.
- دعم عربي/إنجليزي (RTL/LTR) وداكن/فاتح، محفوظان في `localStorage` لكل زائر.
- بنية جاهزة للتوسع: جداول `categories` و `software_options` منفصلة لإضافة عناصر جديدة لاحقًا.

## ما يحتاج استكمالًا (خارج نطاق هذا الأساس البرمجي)

هذا أساس إنتاجي حقيقي يعمل، وليس نموذجًا تجريبيًا مزيّفًا، لكن بعض النقاط في المستند الأصلي تحتاج بناءً إضافيًا فوق هذا الأساس:

- صفحات تعديل/إعادة ترتيب المشاريع (حاليًا: إضافة، نشر/إخفاء، حذف من جدول — التعديل الكامل والسحب-والإفلات لإعادة الترتيب غير مُنفَّذين بعد).
- واجهة لإدارة `categories` و `software_options` من لوحة التحكم (حاليًا تُدار مباشرة من قاعدة البيانات).
- المحرر البصري الكامل (drag-and-drop لإعادة ترتيب الأقسام وإخفائها) — البنية (`site_settings.draft`) تدعمه، لكن واجهة السحب والإفلات نفسها تحتاج بناءً منفصلًا.
- شريط تقدّم فعلي أثناء رفع الفيديوهات الكبيرة (الرفع الحالي يعمل لكن بدون مؤشر نسبة مئوية حي).
- كشف نسبة العرض التلقائي من ملف الفيديو نفسه (حاليًا يُختار يدويًا من القائمة).
- Before/After، لقطات الشاشة، ومحتوى "خلف الكواليس" لكل مشروع.

هذه الإضافات كلها تُبنى فوق نفس البنية (الجداول والصلاحيات جاهزة لها)، ويمكن إضافتها تدريجيًا.
